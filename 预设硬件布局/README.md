# 预设硬件布局

> Status: PRESET / NON-BINDING  
> Scope: Utopia / Digital-City 个人计算工作台的预设硬件拓扑与采购锚点  
> Price snapshot: 2026-10，中国市场参考区间；下单前必须重新询价与核验成色

## 1. 设计定位

这套硬件不是普通桌面 PC，也不是追求极致算力的数据中心集群。

目标是构建一套 **双节点、长期无人值守、可独立运行、可由笔记本临时接入维护的个人计算工作台**：

- 两个主节点为同级别性能与同等能力；
- 任意一个节点都必须能够独立承载完整 Utopia 核心服务；
- 正常情况下采用 **Primary + Warm Secondary**；
- Secondary 保持在线，承担状态复制、备份、健康监控和少量后台任务；
- 高负载时允许双节点并行工作；
- 每月进行一次主负载切换（A → B / B → A），将真实切换同时作为灾备演练；
- Win/Mac 笔记本只用于第一次配置、偶发人工检查和故障维修，不作为工作台运行依赖；
- 手机、PC、Mac 等终端不计入本文件的计算能力基线。

## 2. 目标能力

### 单节点目标

推荐方案的单节点目标为：

- 24–32 个服务器级 CPU 物理核心；
- 256 GB ECC RAM；
- 24–48 GB CUDA GPU 显存；
- 约 8 TB 级镜像后高速工作容量（视最终 ZFS / mirror 布局而定）；
- 独立 BMC/IPMI 管理；
- 10GbE 外部网络；
- 25GbE 双节点物理直连；
- 单节点可独立维持整个工作台核心服务。

工程上的能力锚点：

- **推荐方案单节点：约等价 3 台中高端开发/游戏级 PC 的综合 CPU/RAM 多任务能力**；
- **低价方案单节点：约等价 2–3 台中高端开发/游戏级 PC 的综合能力**；
- **推荐双节点共同工作：约 5–6 台同等级 PC 的实际并行工程能力**。

这里的“等价”指 Utopia 的目标工作负载：Agent、CI、编译、VM、Browser Automation、Computer Use、Vision、本地 AI 推理、数据库和后台服务的综合吞吐，不代表可以把单张 GPU 机械等同于三张独立游戏 GPU。

### 典型单节点资源切分

可将推荐节点粗略理解为：

| 资源域 | CPU | RAM | 典型职责 |
|---|---:|---:|---|
| Utopia / Host | 8C | 80–112GB | Core、Scheduler、DB、Cache、监控、基础服务 |
| Heavy Worker A | 8C | 48GB | Agent / CI / VM |
| Heavy Worker B | 8C | 48GB | Agent / Browser / Computer Use |
| Heavy Worker C | 8C | 48GB | 编译 / 测试 / VM / 后台任务 |

实际运行由调度器动态分配，不要求固定切片。

## 3. 双节点拓扑

~~~text
                    Home LAN / Internet
                          │
                ┌─────────┴─────────┐
                │                   │
             Node A              Node B
          Primary/Secondary   Primary/Secondary
                │                   │
                ╞════ 25GbE ════════╡
                │   Direct Fabric   │
                │                   │
              BMC A               BMC B
                └──── Management ───┘
                          │
                  Temporary Laptop
                    Win / macOS
~~~

### 网络平面

1. **业务网络**：终端、Utopia Client、Internet、普通 LAN。
2. **节点专线**：A ↔ B 的 25GbE SFP28 DAC 物理直连；用于复制、迁移、模型、VM、artifact 和主负载交接。
3. **管理网络**：独立 BMC/IPMI；操作系统失效后仍可开关机、查看 POST、进入 BIOS、挂载安装介质和远程 Console。

节点专线必须使用标准 IP 网络抽象。未来从 25GbE DAC 升级到 50/100GbE、光纤或交换 Fabric 时，不应要求修改 Utopia 上层架构。

## 4. 长期硬件原则

### 4.1 不追代

完成第一次搭建后，预期核心平台至少稳定运行 4–6 年。

只有以下情况才构成升级理由：

- 实际负载持续超过安全余量；
- GPU 显存成为明确瓶颈；
- 存储容量或写入寿命不足；
- 某组件故障或进入不再安全的支持周期；
- 新硬件能够产生明显的维护成本下降，而不是仅提高跑分。

### 4.2 标准件优先

优先使用：

- 标准 PCIe GPU；
- 标准 DDR5 ECC RDIMM；
- 标准 U.2/U.3/M.2 NVMe；
- 标准 SFP28 / Ethernet；
- 标准 ATX/EEB/服务器电源接口；
- BMC/IPMI；
- 可替换风扇、背板和线材。

避免将架构绑定到单一 OEM 的专用主板、专用 PSU、专用 riser、专用硬盘托架或不可替换背板。

### 4.3 国产供应链使用原则

优先考虑国产成熟供应链的：

- 4U / Pedestal 大型机箱；
- 热插拔背板；
- 冗余电源；
- 风扇与线材；
- DAC；
- UPS / 配电；
- 机架、支架和机械结构。

核心计算生态当前默认：

- **CPU：AMD EPYC / x86-64**
- **GPU：NVIDIA CUDA**

不以“全国产”为目标。任何国产 CPU/GPU 替代必须首先证明 Linux/KVM/Docker/CUDA-equivalent 软件栈不会增加 Owner 维护负担。

### 4.4 二手企业件原则

允许并鼓励使用成熟企业退役件降低 TCO，尤其是：

- GPU；
- 25GbE NIC；
- U.2/U.3 企业 NVMe；
- ECC RDIMM。

二手件必须保留验收门槛：

- GPU：完整显存压力测试、ECC/错误检查、温度、功耗和长时压力测试；
- SSD：完整 SMART、Percentage Used、Media Error、写入量、通电时间和固件版本；
- NIC：固件、SR-IOV、链路稳定性和 25GbE 实际吞吐；
- RAM：完整 MemTest / ECC 事件检查。

## 8. 正常运行模式

### 日常

~~~text
Node A = PRIMARY
Node B = WARM SECONDARY
~~~

Secondary 持续执行：

- 数据 / 状态复制；
- DB replica；
- artifact / 关键配置同步；
- 健康监控；
- 少量后台任务；
- 接管准备。

### 高负荷

允许：

~~~text
Node A + Node B = ACTIVE COMPUTE
~~~

但控制面必须始终明确当前 Primary，不能因为双机参与计算而产生双主写入。

### 月度换主

每月进行一次：

1. Secondary health check；
2. replication lag → 0；
3. 当前 Primary 停止接受新任务；
4. 完成/检查点化剩余任务；
5. Promote Secondary；
6. Smoke test 核心服务；
7. 原 Primary 降级为 Secondary；
8. 记录切换结果。

月度切换的主要意义不是“让服务器休息”，而是持续证明灾备节点真实可接管。

## 9. 笔记本维护模型

Win/Mac 笔记本不是常驻控制器。

### 第一次搭建

连接管理网络完成：

- BIOS/BMC；
- Linux/Hypervisor；
- Utopia；
- 网络与 25GbE 直连；
- 存储；
- GPU；
- UPS；
- 自动启动；
- Watchdog；
- Failover。

完成后必须进行一次 **拔掉笔记本后的独立运行验收**。

### 后续检查

不定期重新接入笔记本，仅执行：

- BMC/IPMI 查看；
- 温度/风扇/电压；
- SMART；
- ECC 事件；
- 日志；
- 固件；
- 人工灾备验证；
- 必要时 BIOS / OS 级救援。

即使 Linux、SSH、Utopia 或主业务网络失效，BMC 管理面仍应能够完成开关机、POST/BIOS Console 和安装介质挂载。

## 10. 采购与价格更新规则

本文件的型号是 **采购锚点，不是永久锁定型号**。

实际采购时允许替换，但替代件必须满足同一能力合同：

- CPU：同等级核心数、服务器虚拟化、足够 PCIe lanes；
- RAM：ECC RDIMM，容量不低于基线；
- GPU：优先 CUDA；显存不得在未评估工作负载前随意下降；
- 主板：必须有 BMC/IPMI；
- 网络：必须保留双节点独立高速物理互联；
- 存储：必须保留系统盘镜像 + 节点级复制；
- 电源：长期无人值守场景优先冗余；
- UPS：必须支持安全关机/恢复运行路径。

价格建议在 **正式采购前重新抓取一次**，而不是为了保持 README 的表面“实时性”频繁修改型号。
