## 3. Findings

### N-1 (note, not a repair request) — the api/schema version check no longer runs on the legacy public pairing routes

The change restructured the auth preamble from

```text
if(!publicPairing) auth(req, nodeRoute); version(req);
```

to

```text
if(!publicJoin && !legacyPublicPairing) auth(req, nodeRoute);
if(!legacyPublicPairing) version(req);
```

so `GET /pairing/info` and `POST /pairing/exchange` are now exempt from `version(req)` as well as from `auth()`.

**Why it is not a repair request.** It is fail-open only in the sense that a mismatched client is *served* rather than refused; no authority is granted, no secret is exposed, and the response still carries `apiVersion`/`schemaVersion` so a client can detect the mismatch itself. The rationale in the diff is real: these two routes must be reachable by a **joining** client that has not yet learned the City's versions, and refusing them with 409 was one of the six defects the author found by running the change.

**Why it is still recorded.** It leaves the wire contract **asymmetrical**: `/pairing/session` refuses a bad version with 409 while `/pairing/info` on the same version accepts it. A client that learns "409 means upgrade" from one route will be surprised by the other. The honest repair, if the phase integration wants one, is not to restore the blanket check but to make the exempt routes *explicitly* version-tolerant — e.g. answer the mismatch in the payload (`"versionMismatch": true`) so the exemption is stated rather than implied. **Not required for this acceptance**; the reviewer prefers a truthful, documented exemption to a silent 409 that blocks a legitimate join.

### N-2 (note) — the two-machine topology of section 9 is DEFERRED, not passed

The author's real-LAN acceptance ran the second City **on this host's own LAN interface**. That is real mDNS, real browsing and a real approval gate, but it is **one physical host**, so workbook section 9's Alien+Mech topology is not established by it. The author says so in the development record; this review confirms it and adds nothing. `deferred != passed`.
