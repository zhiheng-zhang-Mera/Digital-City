# RS-202 — Multi-device concurrency awareness and rescheduling

> [Persistent construction rules](../../../../CONSTRUCTION_RULES.md) · [Process data policy](../../../../PROCESS_DATA_POLICY.md). This workbook defines task-specific scope/dependency/acceptance only; persistent rules govern ordinary claims, waiting/wake, CI, independent two-host work and merging.

## Goal

Address slowdown when several devices interact with the same AI/provider/session: sense device, session, provider and local-host pressure; safely reschedule when user keeps the provider, rather than collide repeatedly on one congested path.

## Confirmed behavior direction

- Device count dynamic.
- Provider/model pool dynamic.
- User first chooses whether to switch AI.
- If no switch, scheduler queues/diverts.
- Temporarily no claimable/schedulable resource is not task completion; requires eligibility-aware bounded rescan.
- Ineligibility and temporary resource absence remain separate.
- Results return to current interaction device; user need not go to executor device.

## Allowed change boundary

Scheduler/foreman, routing, device telemetry/presence, queue/lease, load model, related contracts/tests.

## Prohibited change boundary

- No UI redesign.
- CPU/GPU alone does not equal busy device.
- No crossing Remote Fabric trust/permission.
- No infinite sleep/polling for concurrency conflict.
- No discarded request because all providers are currently occupied.

## Construction steps

1. Audit EM-010 foreman scheduler, GAI routing, Remote device/presence contracts.
2. Explainable pressure/eligibility inputs: session/provider concurrency, device load/reachability, policy, user disabling.
3. Routing sequence: current device/provider can run → offer provider switch choice → if declined, scheduler queue/alternate eligible device → bounded retry.
4. Temporary zero-claim uses approximately 20-minute bounded-rescan semantics as upper-policy reference; implementation prioritizes events, avoiding passive waiting.
5. Anti-flap/hysteresis prevents task bouncing across device/provider.
6. Cover simultaneous multi-device submissions, high-load device, congested provider session, offline recovery, eligible set 0→1.

## Independent review

Opposite host race/adversarial tests: duplicate scheduling, dual execution, stale telemetry, expired lease, sudden offline, queue starvation, rescan storms, same-user multi-device fairness.

## Completion gates

- Concurrency pressure affects scheduling without rewriting permission.
- Keeping provider still has explicit queue/cross-device path.
- Transient no-resource is not terminal failure.
- Anti-flap and single-execution/idempotency provable.
- Hosted CI all green.

## Binding persistent rules

Inherit [CONSTRUCTION_RULES.md](../../../../CONSTRUCTION_RULES.md). In particular: Development and Review of one task use different physical hosts; waiting does not occupy a host; zero claims must be classified; WAITING_ELIGIBILITY prioritizes event wake with approximately 20-minute fallback rescans; external recovery requires reconciliation; CI/evidence bind exact head; no make-work or unilateral scope expansion.
