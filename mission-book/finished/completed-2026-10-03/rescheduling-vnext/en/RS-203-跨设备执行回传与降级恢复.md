# RS-203 — Cross-device result return and degraded recovery

> [Persistent construction rules](../../../../CONSTRUCTION_RULES.md) · [Process data policy](../../../../PROCESS_DATA_POLICY.md). This workbook defines task-specific scope/dependency/acceptance only; persistent rules govern ordinary claims, waiting/wake, CI, independent two-host work and merging.

## Goal

Close the execution loop between dynamic provider pool and device-aware scheduler: after transfer to another device/provider, the current device retains observable, cancellable interaction and receives results. Failure has explicit degradation, without requiring user device switching.

## Core invariants

- Interaction device may differ from execution device.
- Execution result/progress/attention returns to canonical/shared state, then projects to current authorized surface.
- Handoff does not transfer permission.
- Retry uses the same action/idempotency semantics to avoid duplicate side effects.
- Remote disconnect state is truthfully unknown/degraded/recovering, not fake success.
- Reasons for provider switch, device handoff and queue fallback are explainable without exposing technical fields by default.

## Allowed change boundary

GAI remote execution, Engineering Manager return-control, Remote Fabric transport adapter, shared task/action integration, recovery tests.

## Prohibited change boundary

- Do not require ordinary-result confirmation on remote machine.
- No second task truth.
- Remote envelope is not domain task model.
- No final UI visual design.

## Construction steps

1. Canonical execution/handoff correlation and progress/result return.
2. Cover remote start/progress/waiting-user/success/failure/cancel/disconnect/recovery.
3. User confirmation returns to current authorized interaction surface; timeout/offline uses explainable recovery.
4. Separate provider unavailable from device unavailable; fallback preserves causes.
5. Bind remote results to provenance/evidence; presentation needs only stable summary fields.
6. Real two-device E2E; mocks supplement edge cases, never replace final cross-device acceptance.

## Independent review

Opposite host verifies actual result return to current device, remote power-off, network recovery, duplicates, out-of-order progress, cancellation races, reduced-permission handoff, mid-run provider/session expiry.

## Completion gates

- At least one success and one recovery path on real two devices pass.
- Current device receives results without walking to another machine.
- No split-brain or duplicate side effect.
- Stable state/reasons usable by UI adapters.
- Hosted CI all green.

## Binding persistent rules

Inherit [CONSTRUCTION_RULES.md](../../../../CONSTRUCTION_RULES.md). In particular: Development and Review of one task use different physical hosts; waiting does not occupy a host; zero claims must be classified; WAITING_ELIGIBILITY prioritizes event wake with approximately 20-minute fallback rescans; external recovery requires reconciliation; CI/evidence bind exact head; no make-work or unilateral scope expansion.
