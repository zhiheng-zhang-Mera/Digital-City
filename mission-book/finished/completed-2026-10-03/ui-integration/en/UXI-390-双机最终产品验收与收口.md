# UXI-390 — Final two-host product acceptance and closeout

> [Persistent construction rules](../../../../CONSTRUCTION_RULES.md) · [Process data policy](../../../../PROCESS_DATA_POLICY.md). This workbook defines task-specific scope/dependency/acceptance only; persistent rules govern ordinary claims, waiting/wake, CI, independent two-host work and merging.

## Goal

Final Utopia UI + rescheduling vNext product acceptance. Technical acceptance mainly uses two hosts/automation; Owner only makes final visual judgment.

## Construction steps

1. Final integration branch from latest main; merge reviewed UXI-301 head.
2. Two-host split: one runs real Web/Android/Rooms user flows and multi-device scheduling; the other independently critiques visuals/regresses/checks error and recovery, directly committing repairs.
3. Cover Home/Ask·Do/Tools/Devices/Activity; at least three Rooms; provider choice including unavailable grey state; queue/scheduler after user declines switching; remote handoff/result return; provider/device failure/recovery; Advanced details reachable but collapsed by default.
4. Another screenshot → critic → repair → screenshot loop until no blocking visual finding.
5. Minimal Owner package: Web Home/Ask/Tools; Android Home/Ask/Tools; one Room; one provider-switch/remote-handoff state.
6. Owner only says attractive or unattractive plus one reason. If unattractive, Agent converts natural-language feedback into concrete changes and continues automatically, without asking Owner for CSS/component lists.
7. Technical and visual pass before Utopia main merge/main CI verification.

## Final completion gates

- All old functions reachable.
- Default UI no engineering console/monitor dashboard language.
- Scheduler vNext genuinely works.
- Real two-device E2E.
- Consistent Web/Android/Rooms visuals.
- Owner final visual gate passed.
- Main hosted CI green.
- Terminal marker UTOPIA_PRODUCT_UI_AND_RESCHEDULING_VNEXT_ACCEPTED.
