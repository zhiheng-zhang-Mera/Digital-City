# UXI-390 — 双机最终产品验收与收口

## 目标
完成 Utopia UI + 再调度 vNext 的最终产品验收。技术验收应尽量由双机和自动化完成；Owner 只做最终视觉判断。

## 施工步骤
1. 从最新 main 建最终 integration branch，合入 UXI-301 已 review head。
2. 双机分工：
   - 一台主机跑真实 Web/Android/Rooms 使用流与多设备调度；
   - 另一台主机独立做视觉 critic、回归、错误态/恢复态检查，并直接提交修复。
3. 至少覆盖：
   - Home / Ask·Do / Tools / Devices / Activity；
   - 3 个以上 Rooms；
   - provider choice（含不可用灰态）；
   - 用户拒绝切换后 queue/scheduler；
   - remote handoff + result return；
   - provider/device failure + recovery；
   - Advanced technical details 可访问但默认折叠。
4. 再跑一轮“截图 → critic → 修复 → 截图”，直到 critic 没有 blocking visual finding。
5. 提交 Owner 的材料必须极简：
   - Web Home / Ask / Tools；
   - Android Home / Ask / Tools；
   - 一个 Room；
   - 一个 provider switch/remote handoff 状态。
6. Owner 只需回复“好看”或“不好看 + 一句原因”。若不好看，Agent 自己把自然语言反馈翻译成具体设计修改，继续自动循环，不要求 Owner 写 CSS/组件清单。
7. 技术与视觉都通过后 merge Utopia main，验证 main CI。

## 最终完成门槛
- 全部旧功能仍可达；
- UI 不再呈现工程控制台/监控大盘为默认语言；
- scheduler vNext 真实工作；
- 双设备真实 E2E；
- Web/Android/Rooms 视觉一致；
- Owner 最终视觉门禁通过；
- main hosted CI 绿；
- 终态标记：
  \`UTOPIA_PRODUCT_UI_AND_RESCHEDULING_VNEXT_ACCEPTED\`。


## 双机领取与并发规则
- Development 与独立 Review 必须由不同实体主机完成。
- claim 后使用独立 branch/worktree；hosted CI、长测试或外部 provider 等待不独占主机。
- 未满足 dependencies 时不得先写未定义的集成逻辑；空闲主机领取同阶段其他可执行任务。
- 普通组件任务不得直接合并 Utopia main；阶段冻结工作书负责 union、回归、CI 与 main merge。
