# RS-203 — 跨设备执行回传与降级恢复

> **常驻施工规则：** [../CONSTRUCTION_RULES.md](../CONSTRUCTION_RULES.md)  
> **过程数据规则：** [../PROCESS_DATA_POLICY.md](../PROCESS_DATA_POLICY.md)  
> 本工作书只定义任务特有 scope / dependency / acceptance；通用 claim、等待/唤醒、CI、双机独立与 merge 规则以常驻规则书为准。

## 目标
把 provider 动态池与设备感知 scheduler 串成完整执行闭环：当工作转交其他设备/provider 后，当前设备继续持有可观察、可取消、可接收结果的交互体验；失败时有明确降级，而不是要求用户换设备操作。

## 核心不变量
- 当前交互设备与实际执行设备可以不同；
- execution result/progress/attention 必须回 canonical/shared state，再投影到当前 authorized surface；
- handoff 不转移权限；
- retry 使用同一 action/idempotency 语义避免重复副作用；
- 远端执行断线时状态必须是 truthful unknown/degraded/recovering，而不是假成功；
- provider switch、device handoff、queue fallback 的原因可解释但不必默认暴露技术字段。

## 允许修改边界
GAI remote execution、Engineering Manager return-control、Remote Fabric transport adapter、shared task/action integration、recovery tests。

## 禁止修改边界
- 不要求用户在远端机器上确认普通结果；
- 不建立第二套任务真相；
- 不把 Remote envelope 当 domain task model；
- 不做最终 UI 视觉设计。

## 施工步骤
1. 建立 canonical execution/handoff correlation 与 progress/result return。
2. 覆盖远端执行开始、进度、等待用户、成功、失败、取消、设备断开、恢复。
3. 用户确认必须回当前 authorized interaction surface；超时/离线走可解释恢复路径。
4. provider unavailable 与 device unavailable 分开处理，fallback 不能混淆原因。
5. 对远端结果做 provenance/evidence 绑定，但 presentation 层只需稳定摘要字段。
6. 做真实双设备 E2E；mock 只能补边缘场景，不能替代最终跨设备验收。

## 独立复核
另一台主机验证：执行结果是否真的回当前设备、远端设备关机、网络中断恢复、重复消息、out-of-order progress、取消竞态、权限降低后的 handoff、provider/session 中途失效。

## 完成门槛
- 真实双设备至少一条成功与一条恢复路径通过；
- 当前设备无需“走到另一台机器”获取结果；
- no split-brain / no duplicate side effect；
- 状态与原因稳定可供 UI adapter 消费；
- hosted CI 全绿。


## 绑定常驻规则
本任务继承 [../CONSTRUCTION_RULES.md](../CONSTRUCTION_RULES.md)。特别是：同任务 Development/Review 不得同主机；等待不独占主机；零领取必须分类；`WAITING_ELIGIBILITY` 事件唤醒优先、约 20 分钟兜底重扫；外部恢复后必须 reconciliation；CI/evidence 必须绑定 exact head；不得制造假工作或擅自扩大范围。

## Reports / evolution
- City 只保存有界结论、SHA、CI 和异常摘要。
- 调度冲突、handoff、fallback、busy/unavailable 样本按 PROCESS_DATA_POLICY 写入 Utopia evolution evidence。
