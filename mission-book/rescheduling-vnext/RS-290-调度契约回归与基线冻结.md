# RS-290 — 调度契约回归与基线冻结

> **常驻施工规则：** [../CONSTRUCTION_RULES.md](../CONSTRUCTION_RULES.md)  
> **过程数据规则：** [../PROCESS_DATA_POLICY.md](../PROCESS_DATA_POLICY.md)  
> 本工作书只定义任务特有 scope / dependency / acceptance；通用 claim、等待/唤醒、CI、双机独立与 merge 规则以常驻规则书为准。

## 目标
集成 RS-201..203，做动态 provider 池、多设备 scheduler、跨设备回传的完整回归并冻结 presentation-facing contract。

## 施工步骤
1. 从最新 Utopia main 建 integration branch，合入已独立 review 的三个组件分支。
2. 统一重复/冲突状态词，不允许 UI 同时面对三套 availability/busy/handoff vocabulary。
3. 输出稳定 presentation-facing 状态与允许动作，例如：
   - provider 可选/不可选及原因；
   - 是否需要用户 provider choice；
   - queued / running / remote handoff / waiting user / degraded / completed；
   - 可取消/重试/继续等待等动作。
4. 状态必须来自 backend truth，不能专门为 UI 捏造假成功。
5. 运行 concurrency、lease/idempotency、device offline/reconnect、provider flap、real two-device E2E。
6. 刷新当时最新 main，重跑 full relevant suite 与 hosted CI。
7. merge main 后记录 SHA/CI，标记 \`RESCHEDULING_BASELINE_FROZEN\`，解锁 UXI-301。

## 独立复核
复核主机必须从 UI consumer 角度检查 contract 是否足够稳定，同时从 scheduler 角度确认 presentation DTO 不反向污染权威状态模型。

## 完成门槛
- RS-201..203 Development+Review complete；
- 统一 scheduler vocabulary；
- 真实双设备 E2E；
- concurrency/recovery/idempotency 全绿；
- main merge + main hosted CI 绿；
- \`RESCHEDULING_BASELINE_FROZEN\`。
