## Objective

Turn existing device-identity lifecycle from backend knowledge into a normal-user-completable recovery flow. Existing GET /api/v0/device/installations, cloneFindings, POST /api/v0/device/installations/:id/rebind, POST .../revoke, UNBOUND/reinstall semantics. Gaps: Web Settings drops cloneFindings, no normal rebind UI, no Android recovery surface.

## Required implementation

### Web

Typed clone/conflict warnings in Settings; enough installation/device identity without secrets; clear UNBOUND recovery state; existing server proof for rebind; safe revoke/remove; never automatically choose logical device for user.

### Android

At least show whether this installation needs recovery and clone/security warnings; complete own-installation recovery where authorized or explicitly guide to Owner Web; no raw token/secret as normal user input.

## Prohibited

Second device registry; bypass rebind proof; clone findings automatically deleting devices; frontend persistence of durable credentials; session credentials promoted to Owner authority.

## Formal Review

Another physical host independently constructs UNBOUND reinstall, legitimate rebind, wrong proof, clone finding, session trying to rebind another installation, self revoke, Owner revoking another installation. At least one actual browser flow. If platform limits Android complete recovery, prove actionable guidance rather than a dead-end status page.

## Mandatory paper material

Original API-present/UI-dropped evidence; pre/post-repair user-path steps; true/false clone cases; rebind refusal codes; reviewer-found privilege/presentation mismatch; every test/runtime failure.

## Completion gate

Complete Web recovery; real actionable Android entry; no silently dropped clone findings; rebind/revoke authority preserved; Development/opposite-host Review PASS; exact-head CI green; complete PAPER_MATERIAL_INDEX; DEVICE_RECOVERY_ENTRY_ACCEPTED marker.
